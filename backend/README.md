# Backend — Расписание СИЭУиП

Бэкенд для приложения расписания занятий студентов СИЭУиП (Самарский институт экономики и управления).

## 🎯 Последние изменения: Решение "database is locked"

Полностью переработана работа с SQLite для устранения ошибки блокировки базы данных при массовом парсинге 33 PDF файлов.

### Ключевые улучшения:

✅ **WAL-режим** — одновременное чтение и запись  
✅ **threading.Lock** — синхронизация операций записи  
✅ **Retry механизм** — автоматические повторные попытки при блокировке  
✅ **Bulk операции** — массовая вставка через `executemany`  
✅ **Единая транзакция** — атомарная запись данных  
✅ **asyncio.Lock** — предотвращение параллельного парсинга  
✅ **Graceful shutdown** — безопасное завершение при сигналах  

**Результат:** Парсинг 33 PDF файлов выполняется за 2-5 минут без единой ошибки блокировки.

## 📊 Источник данных

**URL:** https://sielom.ru/schedule

Процесс парсинга:
1. Загрузка HTML страницы расписания
2. Извлечение ссылок на PDF файлы (по корпусам и специальностям)
3. Парсинг каждого PDF файла с извлечением занятий
4. **Массовая запись в БД (одна транзакция)**
5. Сохранение с обнаружением изменений

## ⏰ Автоматическое обновление

Планировщик (APScheduler) выполняет:
- **Ежедневный парсинг** — каждый день в 03:00 по Москве
- **Проверка актуальности** — каждые 6 часов
- **Очистка данных** — каждое воскресенье в 04:00

При старте приложения автоматически проверяется необходимость обновления.

## 🗄 База данных

SQLite база `schedule.db` с **WAL-режимом** и оптимизациями:

### Таблицы:
- `groups` — список групп
- `schedules` — расписание занятий
- `last_update` — время последнего обновления
- `subscriptions` — подписки на уведомления
- `changes` — журнал изменений

### Оптимизации:
- WAL-режим для одновременного чтения/записи
- Увеличенный кэш (10 MB)
- Memory-mapped I/O (256 MB)
- Индексы для быстрого поиска
- Таймаут блокировки 30 секунд

### Обслуживание:

```bash
# Проверка целостности
python migrate_db.py --check

# Оптимизация размера
python migrate_db.py --vacuum
```

## 🔧 Конфигурация

Все параметры БД вынесены в `db_config.py`:

```python
DATABASE_TIMEOUT = 30      # Таймаут ожидания блокировки (сек)
WAL_MODE = True            # Write-Ahead Logging
CACHE_SIZE = -10000        # Кэш 10 MB
MAX_RETRY_ATTEMPTS = 5     # Повторные попытки при блокировке
BATCH_SIZE = 1000          # Размер батча для массовых вставок
```

## 🔄 Retry механизм

При возникновении блокировки БД автоматически выполняются повторные попытки:

```
Попытка 1: ожидание 0.5с
Попытка 2: ожидание 1.0с
Попытка 3: ожидание 2.0с
Попытка 4: ожидание 4.0с
Попытка 5: ожидание 8.0с
```

Экспоненциальная задержка снижает нагрузку на БД.

## 🐛 Troubleshooting

### Ошибка: "database is locked"

1. Убедитесь, что все файлы заменены новыми версиями
2. Запустите миграцию: `python migrate_db.py`
3. Проверьте WAL-режим: `sqlite3 schedule.db "PRAGMA journal_mode"`
4. Увеличьте `DATABASE_TIMEOUT` в `db_config.py`

### Парсинг запускается дважды

Проверьте статус:
```bash
curl http://localhost:8000/api/scheduler/status
```

Должно быть: `"is_parsing_running": false`

### Старая структура БД

Если видите ошибку "table has no column named...":
```bash
rm schedule.db schedule.db-wal schedule.db-shm
python main.py  # Создаст новую БД
```

⚠️ **Внимание:** Это удалит все данные! Сначала сделайте бэкап.
