# 🚀 Быстрый старт: Внедрение исправлений "database is locked"

## Что было исправлено

Полностью переработана работа с SQLite для устранения ошибки `database is locked` при массовом парсинге 33 PDF файлов.

## Ключевые изменения

### 1. `database.py` — полностью переписан
- ✅ Единое соединение с WAL-режимом
- ✅ `threading.Lock` для синхронизации записи
- ✅ Retry декоратор с экспоненциальной задержкой (5 попыток)
- ✅ `bulk_update_schedule()` — массовая вставка через `executemany`
- ✅ Единая транзакция с `BEGIN IMMEDIATE`

- ✅ `asyncio.Lock` для предотвращения параллельного парсинга
- ✅ Сбор ВСЕХ данных ПЕРЕД записью в БД

### 3. `db_config.py` — новый файл
- ✅ Все параметры конфигурации вынесены отдельно
- ✅ Таймауты, размеры кэша, параметры retry

## Troubleshooting

### Ошибка: "database is locked" всё ещё возникает

1. Проверьте, что все файлы заменены:
   ```bash
   ls -la database.py main.py db_config.py migrate_db.py
   ```

2. Убедитесь, что миграция выполнена:
   ```bash
   python migrate_db.py --check
   ```

3. Проверьте WAL-режим:
   ```bash
   sqlite3 schedule.db "PRAGMA journal_mode"
   # Должно быть: wal
   ```

4. Увеличьте таймаут в `db_config.py`:
   ```python
   DATABASE_TIMEOUT = 60
   ```

### Ошибка: "table schedules has no column named..."

Старая структура БД несовместима. Удалите и пересоздайте:

```bash
rm schedule.db schedule.db-wal schedule.db-shm
python main.py  # Создаст новую БД с правильной структурой
```

⚠️ **Внимание:** Это удалит все данные! Сначала сделайте бэкап.

### Парсинг запускается дважды

Проверьте, что `asyncio.Lock` работает:

```bash
curl http://localhost:8000/api/scheduler/status
# Должно быть: "is_parsing_running": false
```

Если `true` — парсинг завис. Перезапустите приложение.
